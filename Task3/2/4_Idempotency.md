### 4. Механизм обеспечения идемпотентности на входе

Для защиты от дублирования записей (проблема INT-005) используется паттерн **Idempotency Key**. Мобильное приложение при
нажатии кнопки «Записаться» генерирует уникальный `UUID` и отправляет его в заголовке `Idempotency-Key` на API Gateway.

1. Gateway сохраняет ключ в быстром хранилище (Redis) со статусом `IN_PROGRESS`.
2. Если пользователь нажмет кнопку повторно (или произойдет сетевой сбой и клиент отправит retry), Gateway увидит
   существующий ключ и заблокирует создание новой транзакции, вернув текущий статус первой.
3. После завершения саги Gateway обновляет статус ключа на `COMPLETED` и кэширует ответ. При повторном запросе с тем же
   ключом вернется сохраненный ответ, а не произойдет двойная запись или списание.
