### 2. Обоснование выбора системы для Circuit Breaker

**Приоритетная система: 1С («Полисы»)**

**Почему Circuit Breaker важнее для 1С:**
1С — это внутренняя legacy-система, которая деградирует при нагрузке >50 RPS и зависает на 30+ секунд. Если не внедрить
Circuit Breaker, каждый такой запрос будет занимать поток (thread) в API Gateway. При пиковой нагрузке (500+ RPS) пул
потоков быстро исчерпается, и Gateway перестанет отвечать на *любые* запросы (каскадный отказ), включая запросы на
оплату или просмотр анализов.
Платёжный шлюз — это внешний сервис, обычно обладающий высокой отказоустойчивостью. Для него важнее идемпотентность и
асинхронная проверка статусов, чем Circuit Breaker, хотя последний тоже применяется для защиты от сетевых проблем.

**Механизм работы Circuit Breaker для 1С:**

* **CLOSED (Замкнут):** Нормальная работа. Адаптер 1С отправляет запросы. Если процент ошибок превышает порог (например,
  50% из последних 20 запросов завершились тайм-аутом или ошибкой 503), предохранитель переходит в состояние OPEN.
* **OPEN (Разомкнут):** Трафик в 1С блокируется. Все запросы мгновенно (за миллисекунды) получают Fallback-ответ (
  оптимистичную проверку) без фактического вызова 1С. Это дает 1С время восстановиться и защищает API Gateway от
  перегрузки.
* **HALF-OPEN (Полуоткрыт):** Через заданный интервал (например, 30 секунд) предохранитель пропускает один тестовый
  запрос к 1С. Если он успешен — состояние возвращается в CLOSED. Если нет — снова OPEN.
