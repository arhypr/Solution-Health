### Стратегия горизонтального масштабирования

| ИТ-система                                      | Реализация горизонтального масштабирования                                                                                                                                                                                                                                                                     | Ограничение выбранного метода                                                                                                                                                                                                                                                                                       | Описание решения для него                                                                                                                                                                                                                                                                                                                                                                                                         |
|:------------------------------------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Сервис «Расписание»**<br>*(Java, PostgreSQL)* | **1. Уровень приложений:** Запуск нескольких stateless-инстансов (подов) за API Gateway с балансировкой нагрузки (Round Robin).<br>**2. Уровень БД:** Настройка Master-Slave репликации. Чтение (просмотр слотов) переводится на Read Replicas (решает проблему INT-009). Запись (бронирование) идет в Master. | **Ограничение записи (Write Bottleneck):** Все операции бронирования (INSERT/UPDATE) идут в единственный Master-узел PostgreSQL. При пиковой нагрузке (тысячи одновременных записей) возникают блокировки таблицы слотов, и Master не справляется с нагрузкой, даже если приложение масштабировано.                 | **Шардирование (горизонтальное партиционирование) БД по филиалам (городам).** Разделение базы данных на независимые шарды: Москва, СПб, Екатеринбург, Новосибирск. Каждый шард имеет свой Master и Read Replicas. Это распределяет нагрузку записи и изолирует сбои (проблема в СПб не заблокирует запись в Москве).                                                                                                              |
| **CRM**<br>*(Java, PostgreSQL)*                 | **1. Уровень приложений:** Запуск нескольких stateless-инстансов за API Gateway.<br>**2. Уровень БД:** Шардирование базы данных по ключу `patient_id` (например, с использованием Citus или аналогичного расширения).                                                                                          | **Сложность кросс-шардовых запросов (Cross-Shard Joins):** Шардирование по `patient_id` хорошо для поиска конкретного пациента, но делает крайне сложными и медленными запросы, требующие агрегации данных по всем пациентам (например, аналитика по загрузке врачей или поиск пациента по номеру телефона без ID). | **Применение паттерна CQRS (Command Query Responsibility Segregation).** Разделение модели чтения и записи. Запись идет в шардированную БД (PostgreSQL). Для сложных запросов и аналитики данные асинхронно проецируются (через CDC или Kafka) в денормализованное хранилище (например, Elasticsearch). Мобильное приложение для чтения карточек и истории будет обращаться к быстрому поисковому индексу, а не к реляционной БД. |
