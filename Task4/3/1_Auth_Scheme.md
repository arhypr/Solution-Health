### 1. Схема аутентификации пользователей

**Выбранная схема:** OAuth 2.0 с потоком **Authorization Code Flow with PKCE** (Proof Key for Code Exchange) и
протоколом **OpenID Connect (OIDC)** для получения данных профиля.

**Почему выбран этот подход:**

* **Безопасность мобильных устройств:** PKCE защищает от перехвата кода авторизации (code interception) вредоносными
  приложениями на устройстве. В мобильных приложениях нельзя безопасно хранить `client_secret`, поэтому PKCE использует
  динамически генерируемый `code_verifier`.
* **Разделение токенов:** Используются **Access Token** (короткоживущий JWT, 15 минут) и **Refresh Token** (
  долгоживущий, 30 дней, с ротацией при каждом использовании).
* **Способ передачи токена:** Токен передается в заголовке `Authorization: Bearer <JWT>` по защищенному каналу HTTPS (
  TLS 1.3). Хранение на устройстве осуществляется в защищенном хранилище ОС (iOS Keychain / Android Keystore), а не в
  открытом виде (SharedPreferences).
