### 2. Политика Rate Limiting

Для защиты от DDoS-атак, парсинга данных и брутфорса на уровне API Gateway настраиваются следующие лимиты (с
использованием алгоритма Token Bucket или Sliding Window):

| Тип запроса                                                                  | Лимит                                                                                                      | Действие при превышении                                                                                                                                                                                    |
|:-----------------------------------------------------------------------------|:-----------------------------------------------------------------------------------------------------------|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Поиск врачей**<br>*(Публичный, GET /api/v1/doctors)*                       | **20 запросов в минуту** с одного IP-адреса.<br>**100 запросов в минуту** с одного устройства (Device ID). | Возврат HTTP-кода **429 Too Many Requests**. Заголовок `Retry-After: 60`. Блокировка IP на 5 минут при повторном нарушении (защита от скрапинга базы врачей).                                              |
| **Создание записи к врачу**<br>*(Авторизованный, POST /api/v1/appointments)* | **3 запроса в минуту** на одного пользователя (User ID).<br>**10 запросов в минуту** с одного IP.          | Возврат HTTP-кода **429 Too Many Requests**. Временная блокировка пользователя на 10 минут. При подозрении на бот-атаку (много запросов с одного IP) — запрос CAPTCHA или полная блокировка на уровне WAF. |

*Примечание:* Лимиты применяются на уровне API Gateway (например, Kong или Nginx). Для пользователей с легитимным IP (
например, корпоративная сеть клиники) могут быть настроены исключения (whitelist).
