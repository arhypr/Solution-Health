### 3. Меры по защите данных при передаче

Поскольку мобильное приложение обрабатывает персональные данные (ПДн) и медицинскую тайну, применяются следующие
обязательные меры:

1. **Шифрование канала (TLS 1.3):** Все запросы от мобильного приложения к API Gateway должны идти строго по HTTPS с
   использованием TLS версии не ниже 1.3. Отключить поддержку устаревших протоколов (TLS 1.0, 1.1, SSLv3).
2. **HSTS (HTTP Strict Transport Security):** API Gateway должен возвращать заголовок
   `Strict-Transport-Security: max-age=31536000; includeSubDomains`, чтобы принудительно переводить все запросы на HTTPS
   и предотвращать downgrade-атаки.
3. **Certificate Pinning (Закрепление сертификата):** На стороне мобильного приложения (в коде iOS/Android) зашивается
   публичный ключ или хэш сертификата API Gateway. Это защищает от MITM-атак (Man-in-the-Middle) даже если злоумышленник
   установит на устройство пользователя свой корневой сертификат.
4. **WAF (Web Application Firewall):** Перед API Gateway разворачивается WAF для фильтрации входящего трафика. Он
   блокирует SQL-инъекции (решение проблемы INT-006), XSS-атаки и аномальные запросы до того, как они достигнут
   legacy-систем (1С, CRM).
5. **Валидация и санитизация входных данных:** На уровне API Gateway и сервисов-адаптеров строго валидируются все
   входящие данные (JSON Schema validation). Никакие данные от клиента не должны напрямую конкатенироваться в
   SQL-запросы (использование ORM/Prepared Statements).
6. **Защита от подмены сессии (Session Hijacking):** Access-токены (JWT) имеют короткий срок жизни (15 минут) и привязку
   к `Device_ID` (в payload токена). При обнаружении запроса с валидным токеном, но другим `Device_ID` или резким
   изменением геолокации, Gateway инвалидирует токен и требует повторной авторизации (защита от SD-007).
